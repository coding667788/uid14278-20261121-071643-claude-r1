实现路由通告策略的离线模型，仅用符号前缀和虚构站点。每条路由附不可变源区域和允许传播的业务标签，节点间边有导入/导出谓词及逐跳写入标签的有限映射；越过有向边前先用旧标签检查出口，映射后用新标签检查入口。格式接受有限标签集合，不接入路由设备。节点为每个源、目的前缀允许保存多种到达状态，来源区域永不由映射修改；到达状态包含节点、标签、源和前缀，允许拓扑成环但不会重复处理等价状态。安全要求定义哪些接收区域不得观测哪些源和标签组合，服务要求定义业务必须保留的到达条件。
audit 输出每条安全或服务要求的判定；有泄露时给跳数最少、再按边 ID 序列最小的可重放路径，逐跳给出映射前后的标签；服务缺失时输出该发布源的全部可达终态。repair 从允许移除的边中选固定集合，使所有泄露消失且服务依旧满足，最小化停用成本，再按停用边数和 ID 决胜。支持 100 节点、300 边、15 条候选，要求模型和修复查询可复用。测试覆盖一条边上标签改写刚好改变入口判定、拓扑环、多发布源同前缀、删除一条边同时消除多个见证、最短泄露路径被切后仍有另一条，以及没有保持必要服务的修法。

审计再加入故障连续性和多视图等价。每条边有业务优先级、故障域及可降级标签规则，分区失效情景为无故障及任一显式登记的单故障域，发生故障时其关联边全失效。服务需求可要求同一源、前缀到目的区域内两个不同站点各存在合规路径，而且两条路径的内部站点和使用的存活故障域都不相交；端点是否计为内部按路径端点排除。若图中至少有一条可用路径但凑不齐双路径，给出最大可达路径数和见证。任何路径不能到达输入标注的禁止中继站点，且优先级低于业务阈值的边不能充当服务路径；安全泄露仍审计全部边。修复候选除了停用边，还可整体替换边的标签映射，同一边至多执行一种动作。要求一个固定动作集同时通过所有情景，允许每情景选不同合规路径；对已指定的基准情景还必须保留每个源的公开端点可观察标签集，危险端点不在此集合。修复按成本、动作数、升序 ID 决胜。测试加入便宜的规则替换引入下游标签泄露、两条路径不同站点却共享故障域、无故障有双路径但单故障后仅剩一条、保留公开标签集使局部修法失效。所有路径、故障和标签仍为离线虚构配置。

使用 Windows 原生 Python 3.12、标准库和 CPU，从空仓库实现，所有夹具用本地虚构数据。命令格式为 python -m solution <命令> CASE.json，涉及持久状态的命令带 --db DB.sqlite。标准输出为 UTF-8 JSON，同一逻辑输入产生同一结果；结构错误给出可定位的错误码及字段位置。交付可直接运行的样例、README（含完整输入输出定义与复现命令）和可用 python -m unittest discover -s tests -v 执行的断言测试。
